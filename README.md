# 诛仙 · 江湖录

按萧鼎《诛仙》原著剧情做的**单机 MMORPG**，浏览器打开就能玩，也能装到手机主屏离线运行。

**▶ 在线试玩：<https://justin9you.github.io/sword/>**（iPhone 用 Safari 打开 → 分享 → 添加到主屏幕）

- 全部代码手写，**零第三方依赖**：没有游戏引擎、没有 CDN、没有 iframe、没有一张图片
- 人物妖兽全是 Canvas 2D 矢量现画，音效是 WebAudio 实时合成，图标是脚本算出来的 PNG——**一个外部资源文件都没有**
- 装到主屏幕后**完全离线**运行，开飞行模式照玩
- 进度存在本机浏览器里，随时关随时接着打

---

## 先说清楚：这是「单机」的 MMORPG

MMO 那套骨架一样不少——**分区地图、刷怪点、仇恨与脱战、掉落、装备栏、技能树、任务链、世界首领、传送**——
但**世界里只有你一个玩家**。

原因很直接：本项目和 skewers 一样是纯静态托管（GitHub Pages / Cloudflare Pages），**没有服务端**。
真正的多人在线需要账号系统、状态同步和一台长期跑着的服务器，那是另一个工程。

## 玩法

### 四大门派

入道时择一，决定体格、法术与专属兵器，**之后不可更改**。

| 门派 | 功法 | 定位 |
|---|---|---|
| **青云门** | 太极玄清道 | 攻守均衡，剑法与道法并重。新手最稳 |
| **天音寺** | 大梵般若 | 血厚防高，带护盾与治疗，最耐打 |
| **焚香谷** | 离火玄功 | 爆发与范围极高，身板脆，站位就是活路 |
| **鬼王宗** | 噬血玄功 | 吸血续航强，高风险高回报 |

每派 6 个技能，随修为自动参悟，不用点技能点：1-6 快捷键，第 7 格是**法宝**（Q 键）。

### 十二张场景

草庙村 → 龙首峰 → 大竹峰 → 滴血洞 → 河阳城（安全区/商店）→ 死灵渊 → 万蝠古窟
→ 焚香谷 → 狐岐山 → 南疆蛮荒 → 鬼王宗 → 通天峰

一路跟着原著走。每张图一只**首领**：千年竹妖、黑水玄蛇王、兽神、黑心老人、云易岚、小白、鬼王、道玄真人……
去过的地方可以在「山河图」里随时传送（战斗中不行）。

### 兵器与法宝

兵器从**烧火棍**起步，一路到**天琊神剑**、**噬魂棒**、**鬼王古剑**、**诛仙古剑**。
法宝是独立槽位，带主动效果：

| 法宝 | 效果 |
|---|---|
| 噬血珠 | 十秒内伤害的 45% 转为气血 |
| 玄火鉴 | 大范围火伤 + 持续灼烧 |
| 合欢铃 | 周围敌人停手数秒 |
| 摄魂 | 范围定身 |
| 六合镜 | 限时反伤 |
| 七尾蜈蚣 | 毒雾 |

品质分五档：凡品 → 灵品 → 宝器 → 仙器 → 神器。掉落会优先出本门派能用的。

### 主线

15 条任务串起全书：草庙村的黄昏 → 大梵般若 → 血洗草庙村 → 烧火十年 → 滴血洞
→ 死灵渊的女子 → 四灵血阵 → 正道与魔道 → 鬼王 → 诛仙剑阵。

NPC 头顶 **！** 是有任务，**？** 是可以复命。

## 操作

| 键鼠 | 动作 |
|---|---|
| `WASD` / 方向键 | 移动 |
| 鼠标移动 | 瞄准（技能朝鼠标方向放） |
| 左键 / `空格` | 普攻（进入近身范围会自动普攻） |
| `1`-`6` | 门派技能 |
| `Q` | 法宝主动 |
| `E` / 右键 | 与 NPC、传送门交互 |
| `R` | 自动挑一颗合用的丹药吃掉 |
| `B` `C` `K` `L` `M` | 背包 / 角色 / 技能 / 任务 / 山河图 |
| `Esc` | 菜单（音效、存档、重开） |

**触屏**：左半屏按住即出摇杆（跟手指落点走，不固定位置），右下角点技能和「攻/E/药」三个圆钮。

### 几条规则

- **自动普攻**：怪进入近身范围就自己打，不用一直点
- **脱战回复**：站着不动两秒多开始回气血灵力，战斗中不回
- **等级压制**：越级打怪伤害衰减，被越级打伤害放大，上下各封顶 60%。血条上标红的别硬啃
- **死亡**：掉一成当前经验（不会掉级），三秒后在本图出生点复活
- **怪物脱战**：拉太远它会回原地并回满血，拉怪跑是没用的（首领不脱战）
- **背包满了捡不到东西**，会在日志里提醒

## 装到手机

### 方案一：免费静态托管（推荐，不用电脑）

托管一次，以后手机随时开链接就能装。**都是免费的，不用买域名，不用备案。**

**GitHub Pages（本项目用的就是这个）**

1. 把仓库推上 GitHub，并确保仓库是 **公开** 的（免费账号的私有仓库开不了 Pages）
2. 仓库 **Settings → Pages → Source** 选 **`GitHub Actions`**
3. 推一次代码（或去 Actions 页面手动点 Run workflow），`.github/workflows/deploy.yml` 会先跑测试、
   通过后再发布，一两分钟后拿到 <https://justin9you.github.io/sword/>

> 测试没过就不会上线。这点很重要：已经把游戏装到主屏幕的人拿的是缓存版本，
> 线上一旦坏掉，他们下次联网打开就会同步成坏的。

**Cloudflare Pages（不想用 GitHub 的话，拖个文件夹就完事）**

1. 注册 <https://dash.cloudflare.com>（免费）
2. 左侧 **Workers & Pages** → **Create** → **Pages** → **Upload assets**
3. 起个项目名，把 `npm run pack` 生成的部署包解开后整个文件夹拖进去
4. 点 **Deploy**，拿到形如 `https://xxx.pages.dev` 的链接

### 方案二：局域网（手机和电脑同一个 WiFi）

双击 **`启动游戏.bat`**，它会打印手机要访问的地址。

连不上就按顺序排查：

1. **Windows 防火墙**（最常见）。管理员 PowerShell 跑一次。**注意限定 `-Profile Private`**，
   否则这条规则在公共 WiFi 下也会放开 8080 入站，以后任何监听 8080 的开发服务都会暴露给同网段的人：
   ```powershell
   New-NetFirewallRule -DisplayName "诛仙" -Direction Inbound -Protocol TCP `
     -LocalPort 8080 -Action Allow -Profile Private
   ```
   不用了就删掉：
   ```powershell
   Remove-NetFirewallRule -DisplayName "诛仙"
   ```
2. 手机和电脑确认连的是**同一个** WiFi（不是一个 2.4G 一个访客网络）
3. 有些路由器开了「AP 隔离」，关掉

### 在 iPhone 上安装

Safari 打开链接 → 底部**分享**键 → **添加到主屏幕**。
装完从主屏图标进去是全屏的，断网也能玩。

> 必须用 **Safari**，Chrome/微信里打开没有「添加到主屏幕」。

Android：Chrome 打开 → 右上角菜单 → **安装应用**。

## 本地开发

```bash
npm start        # 起本地服务器，默认 8080
npm test         # 逻辑自测 + 无头冒烟测试 + 检查 sw.js 版本号
npm run stamp    # 改完代码后更新 sw.js 的缓存版本号
npm run icons    # 重新生成图标 PNG
npm run pack     # 打部署包 zip

npm run export:unity  # 导出 Unity 数据包（JSON + C# 数据类）
npm run test:unity    # 代码生成器自测 + 检查数据包有没有过期
npm run verify:unity  # 编译一遍生成的 C#（需要 .NET SDK）
npm run gen:fixtures  # 重新生成 C# 对照测试的样本
npm run test:core     # 跑 C# 逻辑层的对照测试（需要 .NET SDK）
```

**不能直接双击 index.html**：Service Worker 只在 http(s) 下注册，`file://` 打开装不了主屏幕、也没法离线。

### 改完代码一定要跑 `npm run stamp`

`sw.js` 里的 `VERSION` 是 PWA 唯一的更新开关。改了代码却没改它，
**已经装到主屏幕的用户会被永久钉死在旧版本上**——standalone 模式没有地址栏也没有刷新按钮。

所以版本号是从**所有被缓存文件的内容哈希**自动算出来的，`npm test` 会校验它有没有过期。

## 代码结构

```
src/
├── config.js        所有数值常量（手感、掉落率、等级曲线都在这调）
├── util.js          随机、数学、ID
├── stats.js         属性体系与等级曲线
├── data/            纯数据，改这里就能加内容
│   ├── sects.js     4 门派 × 6 技能
│   ├── items.js     兵器 / 法宝 / 防具 / 丹药 / 材料
│   ├── monsters.js  怪物图鉴（属性由「等级 × 定位倍率」算出）
│   ├── maps.js      12 张场景：障碍、刷怪表、首领、传送门
│   ├── npcs.js      NPC、对话、商店货单
│   └── quests.js    15 条主线
├── inventory.js     背包与装备（全部返回新对象，不原地改）
├── player.js        玩家状态、升级、加点
├── combat.js        伤害公式、增益减益、持续伤害
├── world.js         碰撞、刷怪、怪物 AI、掉落
├── skills.js        技能释放、弹道、命中结算
├── quest.js         任务推进与交付
├── save.js          存档（逐字段校验，旧存档不会崩）
├── audio.js         WebAudio 音效合成
├── art.js           地形与装饰的矢量画法
├── art-actors.js    人物与 12 种怪物形态的画法
├── render.js        摄像机、绘制顺序、特效、血条飘字
├── input.js         键鼠 + 触屏摇杆
├── ui.js            HUD、小地图、技能栏、日志
├── ui-panels.js     背包 / 角色 / 技能 / 任务 / 传送 / 商店 / 对话
└── main.js          游戏循环、换图、战斗结算、自动存档
```

### 两条设计约束

- **玩家和怪物走同一套伤害公式**，只是属性来源不同。这样"我打它 100，它打我 100"在数值上是自洽的，调平衡不用两头猜。
- **怪物属性不逐只手写**，而是由「等级 × 定位倍率」算出来。调一次 `monsters.js` 里的 `ROLE` 表，全世界的难度曲线一起动。

### 加内容

想加一张图、一件装备、一条任务，基本只动 `src/data/` 下的文件。
`npm test` 里有一整组**数据接线检查**：刷怪表里的怪是否存在、任务指向的 NPC 是否存在、
商店货单的物品 id 有没有拼错、任务目标怪是否真的能在某张图刷出来、出生点有没有压在墙里。
这类错误一旦漏出去就是运行时崩溃，所以让测试来盯。

## 导到 Unity

`npm run export:unity` 把 `src/data/` 下的数据导成 Unity 直接能吃的东西，落在 [export/unity/](export/unity/)：

```
export/unity/
├── Resources/ZhuxianData/*.json   7 份数据（物品 / 怪物 / 地图 / NPC / 任务 / 门派 / 数值常量）
├── Runtime/ZxData.cs              C# 数据类，照着数据自动生成
├── Runtime/ZxDatabase.cs          加载 + 查表
└── README.md                      怎么装进工程、有哪些坑
```

C# 类是**生成**的不是手写的：数据表还在长，手写的类一旦落后，JsonUtility 不会报错，
只会把读不到的字段留成 0，然后你在游戏里追一个"为什么这把剑没有暴击"的鬼。
所以有 `npm run test:unity` 盯着数据包有没有过期，CI 里也单独跑一遍。

这道检查**不挂在 `npm test` 上，也不拦部署**：Unity 数据包过期是另一码事，
不该让网页版跟着上不了线。改完 `src/data/` 只想发网页版，那就不用管它。

搬过去的只有数据。战斗公式、技能行为、任务状态机这些还在 JS 里，属于下一步的事。

## 逻辑层移植到 C#

[csharp/](csharp/) 下是正在往 C# 搬的逻辑层。两个工程：

```
csharp/
├── Zhuxian.Core/     移植过来的逻辑（netstandard2.1，不引用 UnityEngine）
└── Zhuxian.Tests/    对照测试（net7.0 控制台程序，手写断言，零 NuGet 依赖）
```

已经搬完的：属性换算与等级曲线（[stats.js](src/stats.js)）、伤害公式与增益减益（[combat.js](src/combat.js)）、
背包与装备（[inventory.js](src/inventory.js)）、玩家状态机（[player.js](src/player.js)）、
任务推进（[quest.js](src/quest.js)）、场景与怪物 AI（[world.js](src/world.js)）。

还没搬：技能释放与弹道（[skills.js](src/skills.js)）、存档（[save.js](src/save.js)）。

**不需要 Unity**。Core 不引用 UnityEngine，用 `dotnet` 就能编译和测试；
Unity 要到做画面那一步才真正用得上。

### 怎么保证搬过去的数值没变

不是"看着公式一样"，是**拿同一串随机数喂两边，逐条对数**：

1. `npm run gen:fixtures` 把 JS 逻辑跑一遍，但把 `Math.random` 换成确定性的 mulberry32，
   把输入、用掉的随机数、输出全记下来，写进 `csharp/Zhuxian.Tests/fixtures/`
2. C# 侧实现同一个 mulberry32，用同样的种子重放，结果必须一字不差
3. 连**随机数消耗了几个**都要对得上——暴击没触发时该不该多摇一次，
   两边不一样的话，单看一条结果可能碰巧相同，连着打就全歪了

现在是 5596 项断言全过。这套办法真的抓到过东西：数据里的小数原本按 Unity 惯例生成成
`float`，结果 `9.4f` 在写入那一刻就不是 9.4 了，等级一乘、取整一落，气血比网页版少 1。
肉眼绝对看不出来，对照测试一跑就红。

## 存档

存在本机浏览器的 `localStorage`，key 是 `zx.save.v1`。

- 每 20 秒自动存一次，换图、切后台、关页面时也会存
- 只存"算不出来的东西"（等级、加点、背包 id、任务进度），属性和技能都是读档时重算的——
  所以改了数值表，老存档也不会崩
- 读档时逐字段校验：认不出的物品 id 直接丢掉，穿不上的装备自动卸下
- 清空浏览器数据会一并清掉存档。菜单里有「重新开始」
